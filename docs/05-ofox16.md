# OrangeFox 16.0 source build — what worked, what didn't

Status: **experimental, not a working daily recovery**. The working recovery remains
**OrangeFox R12.0** (`vegas_ofox_fixed.img`). This page records the 16.0 source build
results, the bootloader size limit, and the two independent failures.

## Correction: the working image is R12.0, not 14.1

`REPRODUCE.md` is authoritative: the working `vegas_ofox.img` is an **OrangeFox R12.0**
unofficial image (DTB `183530`, 1080×2388 panels) patched with the phone’s stock FT8725
touch module. The README’s older “14.1-based” label was wrong.

- **Working**: OrangeFox R12.0 + stock FT8725 = `vegas_ofox_fixed.img`,
  SHA-256 `ddcc59675552d31d5069925507312aa9128ce12911fff2980088eb664cd445d0`.
- **TWRP 14.1 source**: builds, but its userspace hangs on this A16 vendor.
- **OrangeFox 14.1 source** (`fox_14.1`): newer/experimental control build.
- **OrangeFox 16.0 source** (`fox_16.0`): this page.

The source that should reproduce the working image is the **12.1/R12.0** branch. The 14.1
build is a newer control, not the exact one.

## What failed

1. **16.0 platform + 16.0 recovery** fails at the bootloader (logo then fastboot). The
   16.0-built platform is the leading suspect. The slim size fix did not help, so this is
   not only total size.
2. **16.0 platform + 16.0 recovery slim** also fails at the bootloader.
3. **R12.0 platform + 16.0 recovery** loads, and Android boots, but the 16.0 recovery only
   draws the splash and never reaches the menu. This is a userspace/theme failure, not a
   header/DTB/kernel failure.
4. The slim recovery removed the Chinese theme font (`twqy-microhei.ttf`); the OrangeFox
   theme may need it, so the UI may stop after the splash. The font-kept test was invalid
   because it also removed three panel modules; the phone then couldn’t even draw the
   splash.
5. **Full 16.0 recovery on the R12.0 platform** is 57.45 MB and hits the bootloader size
   limit (logo then fastboot).

## Bootloader size limit

Working data points:

- 54.11 MB hybrid A: loads.
- 55.57 MB OrangeFox R12.0: works.
- 57.45 MB full A: fails.
- 58.37 MB 16.0 source: fails.

The limit is between ~55.57 MB and ~57.45 MB, likely around 56 MB. The font-kept test at
55.19 MB failed for the panel reason, not size.

## pstore

The panic in `dmesg-ramoops-0` is the **old TWRP 14.1** panic (initrd 54,896K). The 16.0
attempts produced **no new kernel panic record**; the failures are bootloader-level or a
userspace hang. Do not treat the old panic as a 16.0 log.

## Remaining clean tests

- Build OrangeFox 14.1 from source; compare to R12.0.
- Build 12.1/R12.0 from source as the true environment control.
- Corrected font-kept 16.0 recovery on the R12.0 platform: keep **all six panel modules**
  and the font, remove Wi-Fi/haptics/debug/OTG to stay at ~55.2 MB. This is the clean test
  of whether the missing font caused the splash/no-menu.
- If the 16.0 recovery still only splashes, the A16 recovery userspace/platform mismatch
  is the blocker; the R12.0 daily recovery remains.

No 16.0 image should be published as a working recovery until a Recovery-mode menu,
touch, and `/data` decryption are confirmed.
